# Слой 3 — корректировка версии 5.0.969 (build 5969)

Эталон: фото-макет `F0F7EB01-... (20261016-170108).jpeg`, 1536×576. Сравнение велось по верхнему фрагменту с цветной вкладкой, крафтовым листом, белой бумагой и кремовой лицевой панелью. Цифры ниже являются оптическими ориентирами по *видимой* области, а не координатами исходных скрытых слоёв дизайна.

## Различие 5.0.968

* Светлая верхняя бумага образовывала закруглённый белый бугор на цветной вкладке.
* Изображение слоя 3 накладывалось поверх крафта, закрывая естественный край складки. В эталоне крафтовая складка находится **перед** верхним белым листом.
* Видимые 3–4 кромки из SVG фактически смешивались в длинный контур после перекрытия лицевой панелью.

## Изменено

1. Создан SVG `dossier-layer3-paper-v5969.svg` (402×26); верхнее плечо сделано плоским, без центральной дуги, задний край смещён влево, завершение кромок укорочено.
2. Внутри SVG сохранены три дополнительные смещённые ступенчатые кромки, с тонким тёплым светотеневым разделением.
3. Для *только слоя 3* изменён порядок наложения с `z-index:3` на `z-index:1` в изолированном canvas. Кожаная вкладка имеет `z-index:1` и находится раньше SVG в DOM, поэтому бумага располагается выше кожи, но ниже крафтового слоя (`z-index:2`) и лицевого (`z-index:4`).
4. Класс `dossier-layer3-rims`, его положение (`top:15px`, width 100%, translateX(-2px), scaleX(.985)) сохранены.
5. Обновлены `APP_VERSION=5.0.969`, `APP_BUILD=5969`, Service Worker, все ссылки версии.

## Проверка

* Запущен реальный Chromium с HTML/CSS/JS приложения; скриншоты при 402 CSS px, DPR2 для КОАП, гражданского, уголовного, КАС.
* В браузерном прогоне отсутствовали ошибки загрузки графики.
* Изменены только файл ресурса слоя 3, его порядок наложения, версия и технические manifest/cache/release файлы. Графические байты слоёв 1/2/4 сохранены.

## Ограничение

По сплющенному исходному JPEG нельзя достоверно измерить невидимые под крафтом области слоя 3 и восстановить текстуру в точности. После исправления проверено, что бумага больше не выглядит отдельно вклеенным белым клином. Pixel-perfect **не подтверждён**; особенно заметна разница между исходным близким планом и реальной карточкой из-за других размеров/ракурсов макета. Финальное подтверждение — по iPhone.
