БАЗОВАЯ ЧИСТАЯ ВЕРСИЯ: 5.0.977 / build 5977.
Следующую сборку создавать ТОЛЬКО из этой и далее из самой свежей очищенной сборки,
не из старых рабочих каталогов 5.0.974/5.0.976 с восстановленными дублями.
Перед каждой выдачей ZIP:
  1) исключать из релиза неиспользуемые SVG, PNG, WebP, макеты, отчёты, тестовые HTML;
  2) сверять каждое имя с актуальными app.js, index.html, CSS, manifest.webmanifest;
  3) оставлять исходные активные файлы без переупаковки/перекодирования;
  4) удалять из CORE и OPTIONAL Service Worker ссылки на удалённые ресурсы;
  5) обновлять APP_VERSION, APP_BUILD, meta app-build, asset cache-busting и CACHE SW;
  6) проверять каждый путь SW и HTML/CSS/JS в архиве, отсутствие 404, целостность ZIP;
  7) запускать новую сборку в мобильном браузере и прилагать реальный скриншот;
  8) не увеличивать количество файлов без обоснования использования новых активных ресурсов.
Графические слои и их точные версии фиксированы до отдельного задания пользователя.
Старые исходники (если понадобятся) остаются в прежних ZIP, НО НЕ ПЕРЕНОСЯТСЯ в будущий релиз.

Начиная с 6.1 (build 6602), публичные версии: 6.1, 6.2, 6.3 и далее (после 6.9 — 6.10). APP_BUILD увеличивается на 1; обновление сравнивает именно build. VERSION.txt: первая строка — публичная версия, вторая — Build: N, третья — Legacy-Version с продолжением прежней нумерации для совместимости со старыми клиентами. После каждого выпуска два архива: Advokat-Calendar-<версия>-FULL-CLEAN.zip и Advokat-Calendar-<версия>-GITHUB-UPDATE.zip (только изменённые файлы).

Проверка обновления: перед выпуском сравнить полные сборки побайтно с фактической базовой версией пользователя. Накопительный ZIP должен включать все отличающиеся файлы относительно заявленной базовой версии (включая изменения CSS из пропущенных релизов). Наложить ZIP на каждую заявленную поддерживаемую базовую сборку; проверить полное совпадение состава и содержимого с целевой полной сборкой и все REQUIRED_SHA256. Не ограничиваться проверкой хешей файлов полного архива.
