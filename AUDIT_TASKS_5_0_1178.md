# Аудит вкладки «Задачи», исходная версия 5.0.1178

Дата: 06.11.2026. Проверено исходное приложение (HTML/CSS/JavaScript/PWA) из полного ZIP версии 5.0.1178, визуальное сравнение с пользовательскими скриншотами и макетом, тестовые состояния в Chromium с автономной загрузкой ресурсов и синтетическими задачами.

## Подтверждённые результаты

1. При 0 задач отображаются три пустые карточки с заголовками: «Требуют внимания», «Остальные задачи», «Выполненные».
2. Для завершённых задач 0/1/4/7 карточка автоматически адаптирует высоту; горизонтального переполнения на 320, 390, 402 и 430 CSS px не выявлено.
3. На Chromium у «Выполненные» один разделитель под заголовком, без повторной полосы в исходном ресурсе. Состояние iOS Safari требует отдельного подтверждения на устройстве.
4. В тесте (2 открытых, из них 2 просрочены; 4 завершённых) сводка показала 2/2/4, что соответствует выбранной логике (просроченные входят в «В работе»).
5. Нижние кнопки «Добавить задачу» и «Шаблоны» открывают соответствующие экраны. Открытие завершённой задачи и возврат её в работу вызываются успешно; показатели сводки изменяются.
6. Расстояние между последней бумажной карточкой и кнопками составило 5 CSS px во всех проверенных тестах. Кнопки оставались кликабельными.

## Недостатки, выявленные в 5.0.1178

### Критические / приоритет P1

**P1. Нарушена синхронизация версий ресурсов PWA.** В `index.html` подключены скрипт, стили, иконки и другие ресурсы с `?v=6177`, при этом `app.js`, `sw.js` и `VERSION.txt` указывают 6178. В CSS завершённых задач встречается самостоятельный запрос `?v=6175`. Это создаёт риск частично устаревшей загрузки после обновления PWA. В диагностической сборке 5.0.1179 обновлены ссылки входной страницы, текущего PNG завершённых задач и служебные версии; функциональность приложения не изменена.

**P1. Сброс прокрутки после завершения/возврата задачи.** В сценарии с длинным списком `#page.scrollTop` до клика составлял 725 px, после завершения задачи — 0 px. Состояние задачи изменилось, но пользователь возвращается к началу карточки. Причина: обработчик пытается восстановить `window.scrollY` вместо `#page.scrollTop`; функция `openMatter` сбрасывает прокрутку листа при перерисовке. Требуется сохранить и восстановить позицию прокручиваемого контейнера с учётом уменьшения высоты списка.

### Средние / приоритет P2

**P2. Футер «Задачи» не выровнен с вкладками «Общее» и «События».** При 390 CSS px позиция общего контейнера: x=16.44 px, ширина=356.38 px; вкладка «Задачи»: x=23.41 px, ширина=357.58 px. Смещение вправо примерно 7 px, несмотря на общие CSS-настройки версии 5.0.1178. Причина — специфичные правила контейнера задач, которые переопределяют общие. Требуется сделать общую геометрическую систему, а не только схожие стили внутри кнопок.

**P2. Длинная категория перекрывает название в узком экране.** При 320 CSS px длинное название категории занимает несколько строк, блок метаданных растягивается до 43 px внутри фиксированной 64-пиксельной строки, из-за чего пересекается с названием. Рекомендуется ограничить категорию одной строкой с многоточием либо адаптировать высоту строки по фактическому тексту, сохранив исходную бумажную форму.

**P2. Неоднозначная дата у завершённой задачи.** Код отображает `due` (плановую дату), если она задана, а не `doneAt` (реальную дату завершения). Это может вводить в заблуждение, если в макете дата понимается как день выполнения. Нужна фиксация семантики: «Срок» или «Выполнено». Пока не изменять без согласования.

### Отдельное наблюдение / приоритет P3

**P3. У вкладки «Журнал» отсутствуют аналогичные нижние кнопки в текущей послойной реализации.** Заявление о полной унификации кнопок на четырёх вкладках не подтверждается: в DOM вкладки «Журнал» `dossier-stage9-action` отсутствуют. Исправлять в отдельном этапе разработки «Журнала», не затрагивая утверждённую вкладку «Задачи».

## Рекомендуемая последовательность

1. Стабилизация PWA-кеширования и проверка обновления на iPhone.
2. Сохранение внутренней прокрутки после чекбокса и повторного открытия задачи.
3. Точное выравнивание футера относительно вкладок «Общее» и «События» на всех контрольных ширинах.
4. Обработка экстремально длинных категорий без наложений.
5. Финальная проверка на iOS Safari с реальным сохранением данных, обновлением Service Worker и переходами между вкладками. Тесты на Chromium не подтверждают специфические проблемы Safari.

## Ограничения проверки

В тестовом контейнере прямое открытие локального HTTP/file адреса блокируется окружением. Использована отрисовка настоящего HTML/CSS/JS через `page.set_content`, а ресурсные запросы подменены чтением файлов той же сборки. Работа хранилища IndexedDB и фактическое кэширование в установленной iOS PWA в таком окружении не подтверждены. Для функциональных сценариев использованы синтетические записи без изменения пользовательских данных. В диагностической версии 5.0.1179 исправлены исключительно номера ресурсов и включён этот отчёт; обнаруженные дефекты интерфейса требуют отдельных этапов исправления.
